## 这个仓库是什么

计算机方向的课程设计和毕业设计，难点往往不在代码本身，而在于：

- 题目选得太大，做到一半发现推不动
- 技术栈选完才发现撑不住自己想要的卖点
- 项目能跑，但讲不清楚设计思路
- 答辩时被问到细节，答不上来

这个仓库把我这几年带学弟妹踩过的坑整理成了几份可以直接用的文档。全部开源，拿去改。

**仓库结构：**

## 一、选题库

> 题目均按学术规范格式整理（基于 XX 的 XX 系统设计与实现）。选之前先看下面三条原则。

### 三条选题原则

1. **场景要具体**。「基于 XX 的高校管理系统」这种题太大，收窄到某个校区、某类人群、某个流程。
2. **技术要能支撑卖点**。选了"数据分析"方向，方案里全是增删改查，一眼就露馅。
3. **别选烂大街题**。「图书管理系统」「学生信息管理系统」这类题目，导师每年看几十份。

## 二、技术选型对照表

> 先选方向，再选技术栈。别反过来。

| 方向 | 推荐技术栈 | 学习成本 | 开发周期 | 适合基础 |
|---|---|---|---|---|
| 管理系统类 | SpringBoot + Vue + MySQL | 中 | 4-6 周 | 学过 Java Web |
| 小程序类 | 小程序原生 / uni-app + 云开发 | 低 | 3-5 周 | 前端基础一般 |
| 数据分析类 | Python + Flask + ECharts | 中 | 4-6 周 | 会用 Pandas |
| 深度学习类 | PyTorch + Flask | 高 | 8-12 周 | 有 Python 和数学基础 |
| 混合类 | 模型 + 系统（前后端分离） | 高 | 10-14 周 | 时间充裕、想冲高分 |

### 三条选型建议

1. **先用熟练的，再用新鲜的**。核心功能用一个你上过手的栈保证跑通，亮点功能再引入新技术。
2. **技术栈要服务卖点**。要突出"算法能力"就必须有真实训练和对比实验；要突出"工程能力"就要有完整的部署和并发处理。
3. **别一次上一套没碰过的组合**。SpringBoot + Vue + Redis + Nginx + Docker 全是第一次用，风险极高。

## 三、答辩问题清单

> 这 20 个问题覆盖了绝大多数答辩场景。提前想一遍，比临场发挥强。

### 选题与背景类

| # | 问题 | 回答思路 |
|---|---|---|
| 1 | 为什么选这个题目？ | 从具体场景切入，说明你观察到的真实问题，别答"因为感兴趣" |
| 2 | 这个题目相比已有系统有什么不同？ | 说清楚 2-3 个具体差异点，最好有对照 |
| 3 | 你的创新点在哪？ | 创新点可以是场景创新、方法组合创新、性能优化，不一定是算法突破 |
| 4 | 需求是怎么调研的？ | 有真实调研数据最好，没有就说清楚调研方法和样本 |

### 技术方案类

| # | 问题 | 回答思路 |
|---|---|---|
| 5 | 为什么选这个技术栈？ | 从项目需求出发，别答"因为熟悉" |
| 6 | 数据库表是怎么设计的？ | 讲清楚核心表的主外键关系和索引策略 |
| 7 | 系统有哪些模块？怎么划分的？ | 按功能域划分，避免按技术层划分 |
| 8 | 前后端怎么交互的？ | 说清接口风格、认证方式、异常处理 |
| 9 | 遇到过什么技术难点？怎么解决的？ | 准备 1-2 个真实的排查过程，这是加分项 |
| 10 | 系统的性能瓶颈在哪？ | 能指出瓶颈比声称"性能很好"更可信 |

### 算法与实验类（深度学习方向）

| # | 问题 | 回答思路 |
|---|---|---|
| 11 | 数据集怎么来的？规模多大？ | 说清来源、划分比例、预处理方式 |
| 12 | 为什么选这个模型？ | 对比至少 2 个方案，说明选择依据 |
| 13 | 做了哪些对比实验？ | 列出基线模型和评估指标，用表格呈现 |
| 14 | 模型的评估指标是什么？为什么用它？ | 分类问题别只说准确率，要提精确率/召回率/F1 |
| 15 | 模型有没有过拟合？怎么验证的？ | 讲清楚验证集策略和早停机制 |
| 16 | 创新点体现在哪？ | 讲清楚你改了什么、为什么改、效果提升多少 |

### 工程与总结类

| # | 问题 | 回答思路 |
|---|---|---|
| 17 | 系统怎么部署的？ | 说清运行环境、依赖管理、启动方式 |
| 18 | 项目做了多久？怎么安排的？ | 用阶段划分回答，最好有时间线 |
| 19 | 有哪些不足？如果重做会怎么改？ | **一定要准备这道题**，能承认不足是成熟的表现 |
| 20 | 这个项目对你未来的意义是什么？ | 关联到你的职业方向，真诚回答 |

## 四、常见问题排查

> 项目跑不起来，先对照这里。还有问题直接开 [Issue](../../issues)。

### 环境配置类

| 现象 | 常见原因 | 排查方向 |
|---|---|---|
| `Port 8080 was already in use` | 端口被占用 | 换端口，或查占用进程 |
| `Access denied for user 'root'@'localhost'` | 数据库账号密码不匹配 | 检查配置文件里的连接串 |
| 前端请求 404 / CORS 报错 | 跨域未配置或代理未生效 | 检查后端 CORS 配置和前端代理 |
| `java: 错误: 无效的源发行版` | JDK 版本与 pom 不一致 | 统一 JDK 版本到 8 / 11 / 17 |
| 依赖下载失败 | Maven 镜像源问题 | 换成国内镜像源 |
| `ModuleNotFoundError` | 虚拟环境未激活 | 确认 venv 已激活、依赖已安装 |

### 项目运行类

| 现象 | 常见原因 |
|---|---|
| 启动成功但页面空白 | 前端未打包、静态资源路径不对 |
| 登录后立刻登出 | Token 或 Session 配置问题 |
| 数据查不出来但表里有数据 | 实体类字段与表字段未映射 |
| 上传文件失败 | 上传目录不存在或无写权限 |
